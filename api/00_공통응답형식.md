# 공통 응답 형식 (ApiResponse)

## 개요

모든 API는 `ApiResponse<T>` 형식으로 응답합니다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `success` | Boolean | 성공 여부 |
| `code` | Integer | HTTP 상태 코드 |
| `message` | String | 응답 메시지 |
| `data` | T (제네릭) | 응답 데이터 (없을 경우 null, JSON에서 제외) |
| `timestamp` | String | 응답 시각 (ISO-8601) |

> `data`가 null이면 JSON 직렬화 시 해당 필드가 생략됩니다. (`@JsonInclude(NON_NULL)`)

---

## 응답 예시

### 성공 (데이터 있음) — 200 OK

```json
{
  "success": true,
  "code": 200,
  "message": "Success",
  "data": { ... },
  "timestamp": "2026-05-06T10:30:00"
}
```

### 성공 (데이터 없음) — 200 OK

```json
{
  "success": true,
  "code": 200,
  "message": "Success",
  "timestamp": "2026-05-06T10:30:00"
}
```

### 생성 성공 — 201 Created

```json
{
  "success": true,
  "code": 201,
  "message": "Created",
  "data": { ... },
  "timestamp": "2026-05-06T10:30:00"
}
```

### 실패 — 400 Bad Request

```json
{
  "success": false,
  "code": 400,
  "message": "에러 메시지",
  "timestamp": "2026-05-06T10:30:00"
}
```

## 페이징 응답 형식 (PageResponse)

페이징이 적용되는 목록 조회 API는 `data` 안에 `PageResponse<T>`가 포함됩니다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `content` | List\<T\> | 현재 페이지 데이터 목록 |
| `page` | Integer | 현재 페이지 번호 (0부터 시작) |
| `size` | Integer | 페이지 크기 |
| `totalElements` | Long | 전체 데이터 수 |
| `totalPages` | Integer | 전체 페이지 수 |
| `first` | Boolean | 첫 페이지 여부 |
| `last` | Boolean | 마지막 페이지 여부 |

### 페이징 응답 예시

```json
{
  "success": true,
  "code": 200,
  "message": "Success",
  "data": {
    "content": [ ... ],
    "page": 0,
    "size": 20,
    "totalElements": 58,
    "totalPages": 3,
    "first": true,
    "last": false
  },
  "timestamp": "2026-05-06T10:30:00"
}
```

## 에러 코드 목록 (ErrorCode)

### 공통 에러

| 코드 | HTTP 상태 | 에러코드 | 메시지 |
|------|-----------|----------|--------|
| C001 | 400 | INVALID_INPUT | 입력값이 올바르지 않습니다. |
| C002 | 500 | INTERNAL_ERROR | 서버 내부 오류가 발생했습니다. |
| C003 | 404 | ENTITY_NOT_FOUND | 요청한 데이터를 찾을 수 없습니다. |
| C004 | 403 | ACCESS_DENIED | 접근 권한이 없습니다. |
| C005 | 400 | BUSINESS_ERROR | 비즈니스 로직 오류 |

### 인증 에러

| 코드 | HTTP 상태 | 에러코드 | 메시지 |
|------|-----------|----------|--------|
| A001 | 401 | INVALID_CREDENTIALS | 아이디 또는 비밀번호가 올바르지 않습니다. |
| A002 | 401 | TOKEN_EXPIRED | 토큰이 만료되었습니다. |
| A003 | 401 | INVALID_TOKEN | 유효하지 않은 토큰입니다. |
| A004 | 403 | USER_DISABLED | 비활성화된 계정입니다. |

### 사용자 에러

| 코드 | HTTP 상태 | 에러코드 | 메시지 |
|------|-----------|----------|--------|
| U001 | 409 | USER_LOGIN_ID_DUPLICATED | 이미 사용 중인 로그인 ID입니다. |
| U002 | 404 | USER_NOT_FOUND | 사용자를 찾을 수 없습니다. |
| U003 | 400 | USER_INVALID_ROLE | 유효하지 않은 역할입니다. |
| U004 | 400 | USER_INVALID_STATUS | 유효하지 않은 상태 변경입니다. |

### SSO 에러

| 코드 | HTTP 상태 | 에러코드 | 메시지 |
|------|-----------|----------|--------|
| S001 | 502 | SSO_CONNECTION_FAILED | SSO 서버 연결에 실패했습니다. |
| S002 | 401 | SSO_VALIDATION_FAILED | SSO 인증에 실패했습니다. |
| S003 | 400 | SSO_INVALID_RESPONSE | SSO 서버 응답이 올바르지 않습니다. |

## 인증 헤더

JWT 인증이 필요한 API는 다음 헤더를 포함해야 합니다:

```
Authorization: Bearer {accessToken}
```

토큰 갱신 시:

```
X-Refresh-Token: {refreshToken}
```
