# 스팀에너지관리 - 공유 데이터 API (단가 입력 · 스팀사용량 원단위)

> **인증**: JWT Bearer Token (플랫폼 공통, `/api/auth/login` 으로 발급)  
> **단가 입력** (2026-11-20 변경): 규격 표 `steam_price`, API `/steam-energy-api/prices/**`, 응답은 `ApiResponse<T>` (`{success, code, message, data}`), 쓰기는 `STEAM_ENERGY_MGMT` 메뉴 권한 필요  
> **스팀사용량 원단위(t17)** (2026-11-20 변경): 규격 표 `steam_energy_ratio_steam_unit`, API `/steam-energy-api/energy-ratio-steam-units?year=`, 응답은 `ApiResponse<T>`. 옛 `energy_fuel_ratio` 셀은 읽기용으로만 남고 더 이상 갱신되지 않는다

## 개요

| 데이터 | 화면 | 저장 위치 |
|---|---|---|
| 시설별 단가 (연/월) | 원단위 일지 › 단가 입력 | **`steam_price` 표** (2026-11-20 부터. 그 전의 `steam_cell_value` / `unit_price_detail` 은 읽기용으로만 남아 있고 더 이상 갱신되지 않는다) |
| 스팀사용량 원단위 (톤·스팀/톤·제품) — 기타 스팀량 포함 | 에너지 회계비용 › 연료비 배분비율 17번째 표 | **`steam_energy_ratio_steam_unit` 표** (2026-11-20 부터. 그 전의 `steam_cell_value` / `energy_fuel_ratio` `t17|*` 는 읽기용) |

> **다른 사이트 안내** — 단가를 `unit_price_detail` 로 읽고 있었다면 `steam_price` 로 바꿔야 한다. 2026-11-20 시점의 값은  
> `sql/module-steam-energy/migration/2026-11-20_unit_price_detail_to_steam_price.sql` 로 옮겨 두었다.

## 1. 단가 입력 — `steam_price`

```sql
-- 열: PRICE_ID, YEAR_NO, MONTH_NO, FACILITY, ITEM_CODE, ITEM_NAME, INPUT_TYPE('DIRECT'|'AUTO'), UNIT, PRICE_VALUE DECIMAL(18,6), REMARK,
--     CREATED_AT, CREATED_BY, UPDATED_AT, UPDATED_BY, DELETED_YN('N'|'Y'), DELETED_AT, DELETED_BY
-- UNIQUE (YEAR_NO, MONTH_NO, ITEM_CODE).  DELETED_YN = 'N' 인 행만 유효하다.
```

| `ITEM_CODE` | `FACILITY` | `ITEM_NAME` | `UNIT` |
|---|---|---|---|
| `lng_unit` | LNG | LNG 단가 | 원/㎥ |
| `comb_bsc` | 복합보일러 | BSC 단가 | 원/톤 |
| `comb_bsc_factor` | 복합보일러 | BSC FACTOR | - |
| `comb_asc` | 복합보일러 | ASC 단가 | 원/톤 |
| `comb_asc_factor` | 복합보일러 | ASC FACTOR | - |
| `comb_bsc_guarantee` | 복합보일러 | BSC 보증량 | - |
| `waste1_fixed_hr` | 폐합성소각로 1호기 | 고정단가 | 원/HR |
| `waste2_steam` | 폐합성소각로 2호기 | 스팀단가 | 원/톤 |
| `waste2_fixed_hr` | 폐합성소각로 2호기 | 고정단가 | 원/HR |
| `fluid_steam` | 유동상소각로 | 스팀단가 | 원/톤 |
| `fluid_fixed_hr` | 유동상소각로 | 고정단가 | 원/HR |
| `newinc_steam` | 신설소각로 | 스팀단가 | 원/톤 |
| `newinc_fixed_cost` | 신설소각로 | 고정비용 | - |

### 조회 — 연도 전체

```http
GET /steam-energy-api/prices/year/2026
Authorization: Bearer {accessToken}
```

```json
{ "success": true, "code": 200, "message": "SUCCESS",
  "data": [
    { "priceId": 12, "yearNo": 2026, "monthNo": 1, "facility": "LNG", "itemCode": "lng_unit", "itemName": "LNG 단가",
      "inputType": "DIRECT", "unit": "원/㎥", "priceValue": 638.13, "remark": null, "createdAt": "2026-01-05T09:12:00", "updatedAt": null }
  ] }
```

페이징이 필요하면 `GET /steam-energy-api/prices?year=2026&month=1&page=0&size=100` (`data` 가 `{content, totalElements, …}`), 한 건은 `GET /steam-energy-api/prices/{priceId}`.

### 저장 — (연·월·항목코드) 업서트

```http
POST /steam-energy-api/prices
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "yearNo": 2026, "monthNo": 3, "facility": "복합보일러", "itemCode": "comb_asc", "itemName": "ASC 단가",
  "unit": "원/톤", "inputType": "DIRECT", "priceValue": 11500 }
```

응답 `data` 는 저장된 행(위와 같은 모양) + `isUpdate`(true = 갱신, false = 신규). 실패는 `success: false` 와 `message`.
`STEAM_ENERGY_MGMT` 메뉴 권한이 없는 계정은 403.

> 단가 입력 화면에서 LNG(`lng_unit`)·유동상(`fluid_steam`)·폐합성(`waste2_steam`) 단가를 고치면 그 달 일별 표  
> (`steam_lng_daily_usage`·`steam_fuel_daily_usage`)에도 서버가 같이 넣는다 (`POST /steam-energy-api/prices/apply-daily`).  
> 다른 사이트가 API 로 단가만 바꾸면 일별 표는 바뀌지 않으므로, 필요하면 같은 요청(`{yearNo, monthNo, itemCode}`)을 이어서 보낸다.

## 셀 저장소 규약 (t17 · 옛 단가)

스팀사용량 원단위(t17)와 2026-11-20 이전의 단가는 전용 테이블이 아니라 **공용 셀 저장소 `steam_cell_value` 한 표**에
`table_name` 으로 논리 표를 나눠 저장한다. 아래는 그 규약이다 (API prefix `/steam/api/tables`, 응답은 `ApiResponse<T>` 로 감싸지 않고 본문 그대로, 메뉴 권한 검사 없음).

| 데이터 | 화면 | `table_name` |
|---|---|---|
| 시설별 단가 (연/월) — **옛 저장소, 읽기용** | 원단위 일지 › 단가 입력 | `unit_price_detail` |
| 스팀사용량 원단위 (톤·스팀/톤·제품) — 기타 스팀량 포함 | 에너지 회계비용 › 연료비 배분비율 17번째 표 | `energy_fuel_ratio` (`row_key` 가 `t17|` 로 시작하는 행) |

같은 DB 를 쓰는 시스템은 API 대신 SQL 로 바로 읽어도 된다 (맨 아래 "DB 직접 조회" 참고).

## 물리 테이블 `steam_cell_value`

```sql
CREATE TABLE steam_cell_value (
    id          BIGINT       NOT NULL AUTO_INCREMENT,
    month       VARCHAR(7)   NOT NULL,   -- 연도('2026') 또는 연월('2026-01'). 아래 두 데이터는 연도 4자리
    year_no     INT          NULL,
    month_no    INT          NULL,
    table_name  VARCHAR(32)  NOT NULL,   -- 논리 표 이름
    row_key     VARCHAR(64)  NOT NULL,   -- 행 식별자 (논리 표마다 규약이 다르다)
    col_index   INT          NOT NULL,   -- 열 번호 (논리 표마다 규약이 다르다)
    cell_value  TEXT         NULL,       -- 값은 문자열. 숫자로 쓰려면 CAST
    created_at  TIMESTAMP, updated_at TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_steam_cell_value_month_table_row_col (month, table_name, row_key, col_index)
);
```

> 표 이름은 2026-10 에 `table_cell_value` → `steam_cell_value` 로 바뀌었다 (로컬·개발서버 반영 완료).  
> API 경로의 `{tableName}` 도 `steam_cell_value` 다.

## 공통 API

| Method | URL | 설명 |
|---|---|---|
| GET | `/steam/api/tables/steam_cell_value` | 셀 목록 조회 |
| POST | `/steam/api/tables/steam_cell_value` | 셀 저장 (유니크 키 기준 upsert) |
| PATCH | `/steam/api/tables/steam_cell_value/{id}` | 셀 부분 수정 |
| DELETE | `/steam/api/tables/steam_cell_value/{id}` | 셀 1건 삭제 |
| DELETE | `/steam/api/tables/steam_cell_value/row-group?month=&rowKey=` | 한 달의 한 행 전체 삭제 |
| DELETE | `/steam/api/tables/steam_cell_value/by-table?month=&tableName=` | 한 달의 논리 표 전체 삭제 |

### GET 목록 조회

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `month` | 선택 | `month` 와 같은 값만 (연도 데이터는 `2026`) |
| `fromMonth`, `toMonth` | 선택 | `month` 가 없을 때 범위 조회 (`BETWEEN`, 문자열 비교) |
| `tableNames` | 선택 | 논리 표 이름, 쉼표로 여러 개 (`unit_price_detail,energy_fuel_ratio`) |
| `page` | 선택 | 기본 1 |
| `limit` | 선택 | 기본 100. **한 해치를 한 번에 받으려면 크게 준다** (`limit=5000`) |

응답은 `ApiResponse` 가 아니라 아래 형태다.

```json
      "created_at": "2026-06-30T17:45:52", "updated_at": "2026-06-30T17:45:52" }
  ],
  "total": 132,
  "page": 1,
  "limit": 5000
}
```

## 2. 스팀사용량 원단위 — 기타 스팀량 포함 (t17) — `steam_energy_ratio_steam_unit`

```sql
-- 열: RATIO_STEAM_UNIT_ID, YEAR_NO, MONTH_NO(1~12), UNIT_PM2, UNIT_PM3, UNIT_PAPER_SUBTOTAL, UNIT_TM3, UNIT_TM4, UNIT_TM5, UNIT_TISSUE_SUBTOTAL (DECIMAL(18,6)),
--     CREATED_AT, CREATED_BY, UPDATED_AT, UPDATED_BY, DELETED_YN('N'|'Y'), DELETED_AT, DELETED_BY
-- UNIQUE (YEAR_NO, MONTH_NO). DELETED_YN = 'N' 인 행만 유효하다.
```

값의 갱신 시점은 그대로다 — 연료비 배분비율 페이지가 그 연도를 열어 계산을 마칠 때 달라진 달만 저장된다.

## 2-구. (참고) 2026-11-20 이전 — `table_name = 'energy_fuel_ratio'`

연료비 배분비율 화면의 17번째 표. 값은 화면이 계산한 결과를 DB 에 남긴 것이다 (아래 "갱신 시점" 참고).

| 컬럼 | 값 |
|---|---|
| `month` | 연도 4자리 (`'2026'`) |
| `year_no` | 연도 |
| `month_no` | 0 (연 단위 표) |
| `row_key` | `t17\|r01` ~ `t17\|r07` (아래 표) |
| `col_index` | **2 = 1월 … 13 = 12월**. 1 은 전년 12월 자리라 이 표에서는 쓰지 않는다 |
| `cell_value` | 톤·스팀/톤·제품 (문자열, 소수). 계산 불가(생산량 0 등)면 `NULL` |

| `row_key` | 행 |
|---|---|
| `t17\|r01` | 제지2 |
| `t17\|r02` | 제지3 |
| `t17\|r03` | 제지 소계 |
| `t17\|r04` | 화장지3 |
| `t17\|r05` | 화장지4 |
| `t17\|r06` | 화장지5 |
| `t17\|r07` | 화장지 소계 |

계산식: `(호기별 스팀사용량 + 기타 스팀량 × 호기별 스팀사용비율) ÷ (제품생산량 kg ÷ 1000)`

```http
GET /steam/api/tables/steam_cell_value?month=2026&tableNames=energy_fuel_ratio&limit=5000
Authorization: Bearer {accessToken}
```

응답 `data` 에서 `row_key` 가 `t17|` 로 시작하고 `col_index` 가 2~13 인 행만 쓴다. 월 = `col_index - 1`.

`energy_fuel_ratio` 의 다른 행(`t01|…` ~ `t16|…`)도 같은 열 규약이다 (`col_index` 1 = 전년 12월, 2~13 = 1~12월).

### 갱신 시점

- 누군가 해당 연도의 **연료비 배분비율 페이지를 열거나 입력값을 고치면** 계산 직후 바뀐 칸만 저장된다.
- 아무도 열지 않으면 마지막으로 연 시점의 값이다. 매월 마감 후 그 연도 페이지를 한 번 열어 두는 운용이 필요하다.
- 엑셀 업로드(`/steam/api/tables/energy-fuel-ratio/import-excel`)를 하면 엑셀의 수식 결과가 먼저 들어가고, 이어서 페이지를 열면 화면 계산값으로 덮어쓴다.

## DB 직접 조회 (같은 DB 를 쓸 때)

```sql
-- 단가 입력 (2026년) — steam_price
SELECT ITEM_CODE, MONTH_NO AS mon, PRICE_VALUE AS price, FACILITY, ITEM_NAME, UNIT
  FROM steam_price
 WHERE YEAR_NO = 2026 AND DELETED_YN = 'N'
 ORDER BY ITEM_CODE, MONTH_NO;

-- 스팀사용량 원단위 — 기타 스팀량 포함 (2026년)
SELECT row_key, col_index - 1 AS mon, CAST(cell_value AS DECIMAL(18,6)) AS unit_value
  FROM steam_cell_value
 WHERE table_name = 'energy_fuel_ratio' AND month = '2026'
   AND row_key LIKE 't17|%' AND col_index BETWEEN 2 AND 13
 ORDER BY row_key, col_index;
```

읽기만 하는 시스템은 쓰기 권한 없이 `SELECT` 만 주면 된다. 값을 넣는 쪽은 유니크 키를 지켜 `INSERT … ON DUPLICATE KEY UPDATE` 로 넣는다
(`steam_price` 는 `(YEAR_NO, MONTH_NO, ITEM_CODE)`, `steam_cell_value` 는 `(month, table_name, row_key, col_index)`).
`steam_price` 에 SQL 로 직접 넣을 때는 `FACILITY`·`ITEM_NAME`·`INPUT_TYPE='DIRECT'` 도 채운다 (NOT NULL).
