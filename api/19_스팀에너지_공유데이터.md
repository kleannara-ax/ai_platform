# 스팀에너지관리 - 공유 데이터 API (단가 입력 · 스팀사용량 원단위)

> **인증**: JWT Bearer Token (플랫폼 공통, `/api/auth/login` 으로 발급)  
> **단가 입력** (2026-11-20 변경): 규격 표 `steam_price`, API `/steam-energy-api/prices/**`, 응답은 `ApiResponse<T>` (`{success, code, message, data}`), 쓰기는 `STEAM_ENERGY_MGMT` 메뉴 권한 필요  
> **스팀사용량 원단위(t17)** (2026-11-20 변경): 규격 표 `steam_energy_ratio_steam_unit`, API `/steam-energy-api/energy-ratio-steam-units?year=`, 응답은 `ApiResponse<T>`  
> **옛 API 없어짐** (2026-11-23): `/steam/api/tables/**` 는 더 이상 없다(404). 이 주소로 읽던 곳은 아래 새 주소로 바꿔야 한다

## 개요

| 데이터 | 화면 | 저장 위치 |
|---|---|---|
| 시설별 단가 (연/월) | 원단위 일지 › 단가 입력 | **`steam_price` 표** (2026-11-20 부터. 그 전의 `steam_cell_value` / `unit_price_detail` 은 갱신되지 않고 API 로도 읽을 수 없다) |
| 스팀사용량 원단위 (톤·스팀/톤·제품) — 기타 스팀량 포함 | 에너지 회계비용 › 연료비 배분비율 17번째 표 | **`steam_energy_ratio_steam_unit` 표** (2026-11-20 부터. 그 전의 `steam_cell_value` / `energy_fuel_ratio` `t17|*` 는 갱신되지 않고 API 로도 읽을 수 없다) |

> **다른 사이트 안내** — 단가를 `unit_price_detail` 로 읽고 있었다면 `steam_price` 로 바꿔야 한다. 2026-11-20 시점의 값은  
> `sql/module-steam-energy/migration/2026-11-20_unit_price_detail_to_steam_price.sql` 로 옮겨 두었다.

## 1. 단가 입력 — `steam_price`

```sql
-- 열: PRICE_ID, YEAR_NO, MONTH_NO, FACILITY, ITEM_CODE, ITEM_NAME, INPUT_TYPE('DIRECT'|'AUTO'), UNIT, PRICE_VALUE DECIMAL(18,6), REMARK,
--     CREATED_AT, CREATED_BY, UPDATED_AT, UPDATED_BY, DELETED_YN('N'|'Y'), DELETED_AT, DELETED_BY
-- UNIQUE (YEAR_NO, MONTH_NO, ITEM_CODE).  DELETED_YN = 'N' 인 행만 유효하다.
```

| `ITEM_CODE` | `FACILITY` | `ITEM_NAME` | `UNIT` |
|---|---|---|---|
| `lng_unit` | LNG | LNG 단가 | 원/㎥ |
| `comb_bsc` | 복합보일러 | BSC 단가 | 원/톤 |
| `comb_bsc_factor` | 복합보일러 | BSC FACTOR | - |
| `comb_asc` | 복합보일러 | ASC 단가 | 원/톤 |
| `comb_asc_factor` | 복합보일러 | ASC FACTOR | - |
| `comb_bsc_guarantee` | 복합보일러 | BSC 보증량 | - |
| `waste1_fixed_hr` | 폐합성소각로 1호기 | 고정단가 | 원/HR |
| `waste2_steam` | 폐합성소각로 2호기 | 스팀단가 | 원/톤 |
| `waste2_fixed_hr` | 폐합성소각로 2호기 | 고정단가 | 원/HR |
| `fluid_steam` | 유동상소각로 | 스팀단가 | 원/톤 |
| `fluid_fixed_hr` | 유동상소각로 | 고정단가 | 원/HR |
| `newinc_steam` | 신설소각로 | 스팀단가 | 원/톤 |
| `newinc_fixed_cost` | 신설소각로 | 고정비용 | - |

### 조회 — 연도 전체

```http
GET /steam-energy-api/prices/year/2026
Authorization: Bearer {accessToken}
```

```json
{ "success": true, "code": 200, "message": "SUCCESS",
  "data": [
    { "priceId": 12, "yearNo": 2026, "monthNo": 1, "facility": "LNG", "itemCode": "lng_unit", "itemName": "LNG 단가",
      "inputType": "DIRECT", "unit": "원/㎥", "priceValue": 638.13, "remark": null, "createdAt": "2026-01-05T09:12:00", "updatedAt": null }
  ] }
```

페이징이 필요하면 `GET /steam-energy-api/prices?year=2026&month=1&page=0&size=100` (`data` 가 `{content, totalElements, …}`), 한 건은 `GET /steam-energy-api/prices/{priceId}`.

### 저장 — (연·월·항목코드) 업서트

```http
POST /steam-energy-api/prices
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "yearNo": 2026, "monthNo": 3, "facility": "복합보일러", "itemCode": "comb_asc", "itemName": "ASC 단가",
  "unit": "원/톤", "inputType": "DIRECT", "priceValue": 11500 }
```

응답 `data` 는 저장된 행(위와 같은 모양) + `isUpdate`(true = 갱신, false = 신규). 실패는 `success: false` 와 `message`.
`STEAM_ENERGY_MGMT` 메뉴 권한이 없는 계정은 403.

> 단가 입력 화면에서 LNG(`lng_unit`)·유동상(`fluid_steam`)·폐합성(`waste2_steam`) 단가를 고치면 그 달 일별 표  
> (`steam_lng_daily_usage`·`steam_fuel_daily_usage`)에도 서버가 같이 넣는다 (`POST /steam-energy-api/prices/apply-daily`).  
> 다른 사이트가 API 로 단가만 바꾸면 일별 표는 바뀌지 않으므로, 필요하면 같은 요청(`{yearNo, monthNo, itemCode}`)을 이어서 보낸다.

## 없어진 옛 API — 바꿔야 하는 곳 (2026-11-23)

공용 셀 저장소 API `/steam/api/tables/**` 는 2026-11-23 에 없앴다. 호출하면 **404** 가 온다.
표 `steam_cell_value` 는 DB 에 남아 있을 수 있지만 2026-11-20 이후 값이 갱신되지 않으므로 읽으면 안 된다.

| 예전에 읽던 방법 | 지금 |
|---|---|
| `GET /steam/api/tables/steam_cell_value?month=2026&tableNames=unit_price_detail` | `GET /steam-energy-api/prices/year/2026` (1절) |
| `GET /steam/api/tables/steam_cell_value?month=2026&tableNames=energy_fuel_ratio` 의 `t17\|*` 행 | `GET /steam-energy-api/energy-ratio-steam-units?year=2026` (2절) |
| `POST /steam/api/tables/steam_cell_value` (단가 저장) | `POST /steam-energy-api/prices` (1절) |
| SQL `SELECT … FROM steam_cell_value WHERE table_name = 'unit_price_detail'` | `steam_price` (맨 아래 "DB 직접 조회") |
| SQL `SELECT … FROM steam_cell_value WHERE table_name = 'energy_fuel_ratio' AND row_key LIKE 't17\|%'` | `steam_energy_ratio_steam_unit` (맨 아래 "DB 직접 조회") |

달라지는 점:

- **응답 모양** — 옛 API 는 본문에 `{data: [...]}` 를 그대로 줬다. 새 API 는 `{success, code, message, data}` 로 감싼다.
- **행 모양** — 옛 API 는 칸 하나가 한 행(`row_key`, `col_index`, `cell_value` 문자열)이었다. 새 API 는 월 하나(또는 연·월·항목 하나)가 한 행이고 값은 숫자다.
  - 단가: `row_key` → `itemCode`, `col_index` → `monthNo`, `cell_value` → `priceValue`
  - 원단위: `col_index - 1` → `monthNo`, `row_key`(`t17|r01` …) → 필드(`unitPm2` …, 2절 표)
- **쓰기 권한** — 새 API 의 쓰기는 `STEAM_ENERGY_MGMT` 메뉴 권한이 필요하다. 읽기는 로그인 토큰만 있으면 된다.

## 2. 스팀사용량 원단위 — 기타 스팀량 포함 (t17) — `steam_energy_ratio_steam_unit`

```sql
-- 열: RATIO_STEAM_UNIT_ID, YEAR_NO, MONTH_NO(1~12), UNIT_PM2, UNIT_PM3, UNIT_PAPER_SUBTOTAL, UNIT_TM3, UNIT_TM4, UNIT_TM5, UNIT_TISSUE_SUBTOTAL (DECIMAL(18,6)),
--     CREATED_AT, CREATED_BY, UPDATED_AT, UPDATED_BY, DELETED_YN('N'|'Y'), DELETED_AT, DELETED_BY
-- UNIQUE (YEAR_NO, MONTH_NO). DELETED_YN = 'N' 인 행만 유효하다.
```

| 옛 `row_key` | 컬럼 | 뜻 |
|---|---|---|
| `t17\|r01` | `UNIT_PM2` | 제지2 |
| `t17\|r02` | `UNIT_PM3` | 제지3 |
| `t17\|r03` | `UNIT_PAPER_SUBTOTAL` | 제지 소계 |
| `t17\|r04` | `UNIT_TM3` | 화장지3 |
| `t17\|r05` | `UNIT_TM4` | 화장지4 |
| `t17\|r06` | `UNIT_TM5` | 화장지5 |
| `t17\|r07` | `UNIT_TISSUE_SUBTOTAL` | 화장지 소계 |

```http
GET /steam-energy-api/energy-ratio-steam-units?year=2026
Authorization: Bearer {accessToken}
```

```json
{ "success": true, "code": 200, "message": "SUCCESS",
  "data": [ { "ratioSteamUnitId": 3, "yearNo": 2026, "monthNo": 1, "unitPm2": 2.158473, "unitPm3": 1.942, "unitPaperSubtotal": 1.99,
              "unitTm3": null, "unitTm4": 2.1, "unitTm5": 1.8, "unitTissueSubtotal": 1.95, "createdAt": "2026-11-20T12:05:00", "updatedAt": null } ] }
```

```sql
-- DB 직접 조회 (2026년)
SELECT MONTH_NO, UNIT_PM2, UNIT_PM3, UNIT_PAPER_SUBTOTAL, UNIT_TM3, UNIT_TM4, UNIT_TM5, UNIT_TISSUE_SUBTOTAL
  FROM steam_energy_ratio_steam_unit
 WHERE YEAR_NO = 2026 AND DELETED_YN = 'N'
 ORDER BY MONTH_NO;
```

### 갱신 시점

- 누군가 해당 연도의 **연료비 배분비율 페이지를 열거나 입력값을 고치면** 계산 직후 바뀐 달만 저장된다.
- 아무도 열지 않으면 마지막으로 연 시점의 값이다. 매월 마감 후 그 연도 페이지를 한 번 열어 두는 운용이 필요하다.
- 엑셀 업로드(`POST /steam-energy-api/energy-excel/fuel-ratio/import-excel?year=`)를 하면 엑셀의 수식 결과가 먼저 들어가고, 이어서 페이지를 열면 화면 계산값으로 덮어쓴다.

## DB 직접 조회 (같은 DB 를 쓸 때)

```sql
-- 단가 입력 (2026년) — steam_price
SELECT ITEM_CODE, MONTH_NO AS mon, PRICE_VALUE AS price, FACILITY, ITEM_NAME, UNIT
  FROM steam_price
 WHERE YEAR_NO = 2026 AND DELETED_YN = 'N'
 ORDER BY ITEM_CODE, MONTH_NO;

-- 스팀사용량 원단위 — 기타 스팀량 포함 (2026년) — steam_energy_ratio_steam_unit
SELECT MONTH_NO AS mon, UNIT_PM2, UNIT_PM3, UNIT_PAPER_SUBTOTAL, UNIT_TM3, UNIT_TM4, UNIT_TM5, UNIT_TISSUE_SUBTOTAL
  FROM steam_energy_ratio_steam_unit
 WHERE YEAR_NO = 2026 AND DELETED_YN = 'N'
 ORDER BY MONTH_NO;
```

읽기만 하는 시스템은 쓰기 권한 없이 `SELECT` 만 주면 된다. 단가를 SQL 로 직접 넣을 때는 유니크 키 `(YEAR_NO, MONTH_NO, ITEM_CODE)` 를 지켜
`INSERT … ON DUPLICATE KEY UPDATE` 로 넣고 `FACILITY`·`ITEM_NAME`·`INPUT_TYPE='DIRECT'` 도 채운다 (NOT NULL).
원단위 표는 화면이 계산해 넣는 값이라 밖에서 쓰지 않는다.

## 에러

| 상태 | 원인 |
|---|---|
| 401 | 토큰 없음/만료 |
| 403 | 쓰기 요청인데 `STEAM_ENERGY_MGMT` 메뉴 권한이 없음 |
| 404 | 없어진 옛 주소(`/steam/api/tables/**`)를 호출함, 또는 없는 ID |
| 500 | DB 에 표가 없는 경우 등 — `sql/module-steam-energy/01_schema.sql` 적용 여부 확인 |
